\section{Описание варианта}
\textbf{Вариант №20: Водоподготовка}\\
\textbf{Предметная область:} Мониторинг датчиков очистных сооружений. Контроль гарантирует соответствие санитарным нормам качества питьевой воды.\\
\textbf{Основные метрики (поля датасета):}
\begin{itemize}
    \item \texttt{ts} (int32) -- время замера (Unix timestamp);
    \item \texttt{filter\_id} (int16) -- идентификатор фильтра;
    \item \texttt{turb} (float32) -- турбидность, NTU;
    \item \texttt{ph} (float32) -- кислотность воды;
    \item \texttt{cl} (float32) -- остаточный хлор, мг/л;
    \item \texttt{flow} (float32) -- расход воды, м\textsuperscript{3}/ч.
\end{itemize}

\textbf{Условия фильтрации и очистки:}
\begin{itemize}
    \item \texttt{turb < 0} $\rightarrow$ 0; \texttt{cl < 0} $\rightarrow$ 0 (физическая невозможность отрицательных значений);
    \item \texttt{ph} обрезается (clip) по диапазону $[6.5; 8.5]$ согласно санитарным нормам;
    \item Выбросы по турбидности заменяются медианой группы (IQR-метод по \texttt{filter\_id});
    \item Редкие фильтры ($<1\%$ от общего объёма) агрегируются в категорию \texttt{0}.
\end{itemize}

\textbf{Группировка и оконные функции:}
\begin{itemize}
    \item Группировка по \texttt{filter\_id}: расчёт среднего \texttt{turb} (эффективность очистки) и максимума \texttt{flow} (нагрузка на систему);
    \item Скользящее окно $k=35$: расчёт \texttt{turb\_ma} для выявления долгосрочных трендов;
    \item \texttt{np.diff(flow)} $\rightarrow$ изменение расхода между замерами (индикатор работы насосов или засорения).
\end{itemize}

\textbf{Акцент аналитики:} Обратная зависимость чистоты воды и турбидности. При фильтрации аномалий каждый параметр обрабатывается независимо, без взаимного влияния масок.\\
\textbf{Типы графиков:} Линейный (динамика по неделям), столбчатый (сезонная агрегация), точечный (pH vs turbidity с цветовым кодированием статуса), гистограмма (распределение турбидности).

% ==================== 5. АНАЛИЗ РЕЗУЛЬТАТОВ ====================
\section{Анализ результатов}
В ходе выполнения лабораторной работы были получены следующие аналитические инсайты и выявлены системные ограничения:

\textbf{Полученные инсайты:}
\begin{itemize}
    \item Применение скользящего среднего (\texttt{window=35}) эффективно сглаживает шумовые выбросы турбидности, позволяя чётко выделить долгосрочные тренды эффективности фильтрации. Резкие пики на сырых данных соответствуют кратковременным перегрузкам насосов, а не системному ухудшению качества воды.
    \item Независимая обработка масок аномалий (IQR для \texttt{turb}, clip для \texttt{ph}) предотвращает каскадное искажение данных. Цветовое кодирование \texttt{ph\_status} на scatter-plot наглядно демонстрирует отсутствие прямой линейной корреляции между кислотностью и мутностью, что подтверждает необходимость раздельного контроля параметров.
    \item Агрегация по сезонам выявляет, что максимальные значения турбидности приходятся на весенний период (паводковые нагрузки), что коррелирует с увеличением \texttt{flow}.
\end{itemize}

\textbf{Выявленные ограничения:}
\begin{itemize}
    \item Архитектура Tkinter является однопоточной. При обработке датасетов свыше $10^7$ строк пересчёт \texttt{groupby()} и отрисовка Seaborn могут вызывать кратковременные <<фризы>> интерфейса.
    \item Статический рендеринг Matplotlib/Seaborn не поддерживает аппаратное ускорение GPU, что ограничивает частоту обновления в режимах реального времени (Real-time streaming).
    \item Использование \texttt{canvas.draw\_idle()} ставит задачу в очередь событий, но не гарантирует мгновенного отражения данных при частых изменениях ползунков или фильтров.
\end{itemize}

\textbf{Пути масштабирования решения:}
\begin{enumerate}
    \item Перенос тяжёлых вычислений в фоновый поток с использованием \texttt{root.after()} или \texttt{queue.Queue} для безопасной передачи результатов в GUI-поток.
    \item Замена Seaborn на \texttt{Plotly} или \texttt{Bokeh} для нативной поддержки WebGL-ускорения и интерактивного масштабирования без потери производительности.
    \item Интеграция \texttt{Dask DataFrame} или \texttt{Polars} для распределённой обработки данных, выходящих за пределы RAM, с сохранением логики фильтрации на уровне API.
\end{enumerate}

\section{Выводы}
В ходе выполнения лабораторной работы были успешно освоены ключевые технологии создания интерактивных аналитических панелей в экосистеме Python:
\begin{itemize}
    \item Реализована событийно-ориентированная архитектура с использованием callback-функций и цикла событий \texttt{mainloop()}, что обеспечило мгновенный отклик интерфейса на действия пользователя.
    \item Освоено встраивание графических объектов Matplotlib в оконную систему Tkinter через адаптер \texttt{FigureCanvasTkAgg}, включая корректную работу панели навигации (\texttt{NavigationToolbar2Tk}).
    \item На практике применены методы динамической фильтрации (\texttt{df.loc[]}), агрегации (\texttt{groupby().agg()}), оконных функций (\texttt{rolling()}) и биннинга (\texttt{pd.cut()}) библиотеки pandas. Соблюдено правило обязательного копирования данных (\texttt{.copy()}) для предотвращения \texttt{SettingWithCopyWarning} и искажения исходного датасета.
    \item Разработано устойчивое процедурное приложение без использования ООП-паттернов, что упростило отладку и чтение кода.
\end{itemize}

\textbf{Трудности:} Основным вызовом стала синхронизация состояния данных между этапом предобработки и этапом отрисовки. Некорректное использование ссылок на DataFrame приводило к накоплению артефактов на графиках. Проблема была решена строгим разделением \texttt{df\_processed} (статический эталон) и \texttt{df\_work} (рабочая копия), а также использованием \texttt{fig.clear()} перед каждой отрисовкой.\\
\textbf{Пути улучшения:} Добавление логгирования событий, внедрение прогресс-баров для длительных вычислений, поддержка темной темы интерфейса и автоматическое сохранение состояния фильтров между сессиями.
