\section*{Задание 4: Разработка веб-сайта с интерактивными сценариями}
\subsection{Постановка задачи}
\noindent
Название веб-приложения: Визуализатор нормального распределения \\
Описание функционала: Поля ввода: среднее значение ($\mu$) и стандартное отклонение ($\sigma$). По нажатию кнопки генерируется массив случайных чисел, распределённых по нормальному закону с заданными параметрами, и строится гистограмма («колокол»).\\
Связь с инженерией данных / ML: Статистический анализ данных, визуализация распределений, проверка гипотез.
\subsection{Гипотеза и системный промпт}
Первая гипотеза:
Модель способна самостоятельно спроектировать полное веб-приложение, если чётко описать требования к функционалу, внешнему виду и обработке ошибок.
Однако для получения качественного результата необходимо применить технику ролевого моделирования и разделения ответственности (генерировать HTML, CSS и JS последовательно).\\
\newline
\indent
Системный промпт для основной модели (gemini-3):
\textit{Ты – Senior Frontend Developer, специализирующийся на визуализации данных. Твоя задача – помочь разработать одностраничное веб-приложение «Визуализатор нормального распределения». Пользователь вводит среднее значение ($\mu$) и стандартное отклонение ($\sigma$). После нажатия кнопки приложение генерирует 10000 случайных чисел, распределённых по нормальному закону с этими параметрами, и строит гистограмму (количество столбцов – 30–40), которая должна визуально напоминать колоколообразную кривую. Для построения графиков используй библиотеку Chart.js. Реализуй валидацию ввода: $\mu$ – любое число, $\sigma$ > 0, поля не должны быть пустыми. При ошибке выводи понятное сообщение. Интерфейс должен быть современным, адаптивным, с тёмной или светлой темой на выбор. Отвечай последовательно: сначала предложи структуру HTML, затем CSS, затем JavaScript. После каждого этапа я буду давать обратную связь.}\\
\newline
\indent
Обоснование ролевой установки:
Роль Senior Frontend Developer направляет модель на использование лучших практик (семантическая вёрстка, модульный JS, обработка ошибок) и актуальных библиотек (Chart.js), а не примитивных решений. \\

\textbf{Итерация 3 – генерация JavaScript логики} \\
\indent
Промпт:
\textit{
Напиши JavaScript-код, который:
\begin{itemize}
	\item По нажатию на кнопку считывает $\mu$ и $\sigma$, проверяет их ($\sigma$ > 0, оба поля не пустые). При ошибке – выводит сообщение в блок id="error-message".
	\item Генерирует 10000 случайных чисел, распределённых по нормальному закону, используя преобразование Бокса — Мюллера.
	\item Строит гистограмму с 40 столбцами (bins) на основе сгенерированных данных.
	\item Отображает гистограмму с помощью Chart.js, накладывая теоретическую кривую нормального распределения для сравнения (опционально, но желательно).
	\item Обрабатывает случай, когда старый график уже существует (уничтожать предыдущий экземпляр Chart).
	\item Используй id элементов: mu-input, sigma-input, generate-btn, distribution-chart, error-message.
\end{itemize}
}
\noindent

Для активации JS надо добавить строчку <script src="index.js"\ ></script> в body в конец. \\

Анализ результата:
\begin{itemize}
	\item Код рабочий, использует Box-Muller для генерации нормальных чисел.
	\item Гистограмма строится корректно, наложена теоретическая кривая – это улучшает понимание.
	\item Но есть потенциальная проблема: при большом разбросе данных столбцов может быть слишком много, но 40 – разумно.
	\item Также отсутствует обработка случая, когда все данные одинаковы (sigma=0 не допускается, но если sigma очень маленькая, binWidth может стать нулевым). Добавим проверку.
\end{itemize}

В ходе выполнения задания наиболее эффективными техниками промпт-инжиниринга оказались:
\begin{itemize}
	\item Ролевое моделирование (Senior Frontend Developer) – направляло модель на использование правильных инструментов и архитектуры.
	\item Разделение ответственности – последовательная генерация HTML, CSS и JS позволила контролировать качество каждого слоя и легко вносить изменения.
\newpage
	\item Итеративное уточнение – на каждом этапе я анализировал ответ и давал конкретные корректировки (добавить обработку нулевой ширины, предупреждение при большом $\sigma$).
\end{itemize}
Без этих техник модель могла бы выдать либо слишком примитивный график (без теоретической кривой), либо нестабильный код.
